# Response To Reviewers

Use this when the user needs to plan, draft, or audit a response-to-reviewers letter, revision package, or respectful disagreement with reviewer comments.

## The job of this topic

Make the editor's decision easier by showing exactly how each reviewer concern was handled. The response should be complete, calm, specific, and tied to manuscript changes.

## Default workflow

1. For a full revision, preserve every reviewer/editor point and subpoint in a working response document; for a requested single reply, retain just the context needed to answer it.
2. Classify each point: accepted change, clarification, new analysis, new experiment, claim narrowing, disagreement, editor-only issue, or impossible/out-of-scope request.
3. For accepted points, state what changed and where.
4. For misunderstandings, inspect whether clearer manuscript wording would help readers. Make useful clarifications; otherwise explain the existing evidence and why no change is needed.
5. For disagreements, acknowledge the concern, give evidence or constraints, and offer a bounded change when useful.
6. For requested new work, decide whether the current claim needs it before considering cost. If it does, obtain the evidence or revise/remove the unsupported claim. If it does not, explain a justified non-change, or add a limitation or future direction when useful.
7. When comments appear to conflict, first see whether a coherent revision can address both. Ask the editor when a material conflict or editorial instruction remains unresolved.
8. For a complete letter, summarize important actual changes and unresolved constraints; do not invent an overview package for one local reply.
9. Final-check that reviewers can follow the response without searching the manuscript.

## Decision rules

- If multiple reviewers raise the same issue, address it once in the summary and again at each relevant point.
- If reviewers conflict, explain the consistent resolution in the relevant responses; seek editor guidance when the remaining tradeoff affects the revision strategy.
- If a reviewer asks for a citation, analysis, or experiment that is inappropriate, explain why and offer a text change or limitation if it addresses the underlying concern.
- If the user did not do requested work, do not pretend it was done. State why and revise the claim or limitation if the available evidence requires it. Cost alone does not establish that a request is unnecessary.
- If a reviewer misunderstood existing text, consider manuscript clarity first; quote or summarize the relevant context in the response even when no edit is justified.
- If the response sounds defensive, convert it to concern, action, location, and rationale.
- If useful when emotions are high, make a private thinking draft, then write a calm, evidence-based submitted response; a venting draft or waiting period is optional.

## Adequate answers and version clarity

Advice to comply with every request, even one considered flawed, is a tactic rather than scientific authority. Do not perform invalid analysis to appease a reviewer or hide necessary evidence in a response-only figure. Decide what the retained claim needs; a scientifically justified existing analysis can remain, and a reviewer misunderstanding does not automatically require an apology or manuscript edit. Check whether the reply supplies an explanation that the manuscript itself needs.

Keep each reviewer's section complete on its own. Repeat relevant reasoning, quotations and locations when points overlap rather than send one reviewer to another's answer. Distinguish original reviewer wording, the author's reply and quoted manuscript changes with clear typography. Identify whether a passage or analysis was already present, changed now, completed, proposed or still unknown. State whether line numbers refer to the original or revised manuscript.

Quote manageable changes when they make verification easier; summarize a very large addition and give its precise section instead of copying pages. A long reply with few manuscript edits can be justified only when the public account is already adequate. A response-only result can answer a specific question only if the published conclusions remain assessable without it.

## Variants and edge cases

- **Major revision with many comments:** Build a table before drafting prose so no point is lost.
- **Reviewer overreach:** Separate the valid underlying concern from the excessive requested experiment.
- **Wrong reviewer claim:** Correct the record calmly and cite the manuscript location or new clarification.
- **Conflicting reviewer demands:** Explain the tradeoff to the editor and show a consistent decision.
- **No manuscript change:** Justify why no change is needed and make sure the decision is not merely defensive.

## Anti-patterns

- Skipping hard reviewer sub-points.
- Writing "done" without saying what changed or where.
- Answering with irritation, sarcasm, or claims about reviewer competence.
- Overpromising analyses, experiments, or claims that were not performed.
- Letting the response letter become less organized than the reviews.
- Treating every request as mandatory when claim narrowing would solve the problem.

## Diagnostic questions

- Is every numbered point answered?
- Does each accepted comment include a manuscript location?
- Are new experiments, new analyses, clarifications, and text edits distinguished?
- Does disagreement include evidence, constraint, and a bounded alternative?
- Were misunderstandings inspected for a useful clarification, and is any non-change explained?
- Can the editor see the major revision package in the opening summary?
- Are unresolved issues explicitly named rather than hidden?

## Output patterns / mini-templates

**Opening summary**

```text
We thank the editor and reviewers for their constructive feedback. In the revised manuscript, we have [major change 1], [major change 2], and [major change 3]. We also clarified [topic] and narrowed [claim] to match the available evidence.
```

**Accepted change**

```text
Reviewer comment: [quoted or paraphrased comment]

Response: We agree and have revised [section/location] to [specific change]. This change clarifies [reason].
```

**Respectful disagreement**

```text
Reviewer comment: [comment]

Response: We appreciate the concern. We have not performed [requested work] because [evidence/constraint/scope reason]. To address the underlying issue, we revised [location] to [claim limit, limitation, or clarification].
```

**Reviewer misunderstanding**

Use this wording only when a useful manuscript clarification was actually made. Otherwise explain the existing context and justified non-change.

```text
Response: This comment showed that our original wording was unclear. We revised [location] to state [clarification] and now distinguish [A] from [B].
```

**Response map row**

```text
Reviewer/comment: [number and short label]
Original concern: [quoted or paraphrased concern]
Response type: [change/clarification/analysis/claim limit/disagreement/editor note]
Manuscript change: [what changed or why no change was made]
Location: [section/page/line/table/figure]
```

## Examples

- "We did not add a new animal cohort. Instead, we narrowed the claim from organism-level efficacy to the measured cellular response and added a limitation explaining that organism-level validation remains future work."
- "Reviewer 1 requested more mechanistic detail, while Reviewer 2 asked us to shorten the discussion. We added two sentences that specify the mechanism and removed a speculative paragraph so the section is clearer but not longer."

## When not to apply this

Do not use this playbook for writing the peer review itself. Use it when the user is the author responding to reviews or preparing a revision package.
