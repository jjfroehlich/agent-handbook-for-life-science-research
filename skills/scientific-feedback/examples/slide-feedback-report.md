# Slide Feedback Report

Use this as an output pattern for talk or slide-deck feedback.

## Completed closed fictional critique

**Given.** A fictional researcher supplies a text outline for a six-minute mixed-biology talk: slide 1 asks whether cue removal changes a cultured-cell response; slides 2–4 list protocol details; slide 5 describes the exposed/control comparison; slide 6 gives the bounded result. Both comparison groups and an assay caveat are specified in the outline. No slide images, rehearsal or timing measurements are supplied. The request is to improve explanation order and evidence communication, retaining the caveat.

**Completed feedback.** Keep the exposed/control comparison and its assay limitation. Move a concise explanation of that comparison after the opening question so listeners know what the evidence can answer. Compress the three protocol slides to the details needed to interpret that comparison; retain the control and caveat rather than using the saved space for a stronger claim. Finish with the bounded result. This is a proposed ordering repair, not a measured timing improvement. Inspect the actual slides before judging projected labels or visual hierarchy, and rehearse the revised outline to see whether it fits six minutes.

**Integration.** Communication and evidence-display lenses address the same listener problem. The text supports ordering advice, while exact visual changes remain conditional. This is not a code or analysis review.

## Pattern

Choose the useful fields for the requested depth.

```text
Scope: <talk/deck> for <audience, time, venue>.
Selected lenses: scientific-communication; add data-visualization-and-figures or scientific-writing if relevant.

Core message:
- <one sentence the audience should remember>

Top priorities:
1. <structure/cut/visual issue -> action -> rationale>
2. <slide or figure issue -> action -> rationale>

Slide-level notes:
- <slide/group>: <one job and fix>

Delivery/Q&A:
- <likely question or rehearsal move>

Next step:
- <revision or rehearsal action>
```

## Weak vs strong

Weak: "Add more visuals and make the talk engaging."

Strong when the supplied outline lacks orientation: "Explain the model or comparison before secondary assay details, then compress protocol text that does not affect interpretation and give the result a clearer explanation. Rehearse to check timing; this edit alone does not establish time saved."

## Bad assistant behavior

- Treating the talk like a manuscript.
- Fixing typography before the message and cuts are clear.
- Ignoring time limit and audience background.
