# Introductions

Use this when the user needs help with an introduction, gap statement, significance paragraph, aims paragraph, scope statement, or thesis opening.

## The job of this topic

An introduction gives readers the context and reason for this work, then identifies its actual contribution or purpose. An unresolved question, disputed assumption, practical limitation or useful replication can motivate it. Being previously unstudied alone does not establish importance, and the study need not be the only reasonable next step.

## Default workflow

1. Name the audience and how much background they already have.
2. Establish the territory with only the context needed to understand the problem.
3. Identify the specific uncertainty, limitation, contradiction or other need supported by the supplied literature context. Do not manufacture an empty field to justify the work.
4. Explain the consequence of addressing that need, distinguishing a demonstrated contribution from a potential use or benefit.
5. State the aim, objective, question, hypothesis, or contribution, keeping those categories distinct.
6. Preview the approach, scope, limitations, or structure only as much as needed for orientation.
7. For thesis introductions, use the applicable requirements and actual chapter roles to decide how much background, critical review, approach, scope and navigation belong here. These are reader needs, not a fixed list of sections or paragraphs.

## Decision rules

- If the opening is a broad field survey, compress it to the facts needed for the gap.
- If the gap is phrased as "little is known," specify what is unknown, for whom it matters, and why prior work is insufficient.
- If an early aim is unintelligible, add the necessary context. An early high-level question can also orient readers before a fuller explanation; do not reorder it automatically.
- If a separate thesis review chapter carries the critical comparison, keep enough introductory context to orient readers without duplicating it. If no separate chapter does that work, substantial critical review may belong in the introduction.
- If the final paragraph overpromises, align the stated contribution with the actual results or chapter scope.
- If a significance paragraph lists beneficiaries generically, retain only a supported connection between the contribution and its possible use. Do not invent a benefit mechanism, societal impact or beneficiary to fill a template.
- If aims, objectives, and questions blur together, rewrite the aim as purpose, objectives as tasks, and questions as interrogatives.
- If an introduction was written before the project matured, align its questions and roadmap with the completed work. Preserve the distinction between an exploratory question and a prespecified hypothesis.
- If the opening contains a contradiction or field tension, make that tension the narrowing path instead of adding more background.
- If a sentence confuses what the researchers did with what the document presents, clarify that distinction. A research-action sentence and a navigation sentence serve different purposes; their tense and subject are conventions rather than universal grammar rules.

## Variants and edge cases

- Thesis introductions can tolerate more background than paper introductions, but still need a visible narrowing path.
- Significance sections should distinguish scientific significance from personal or institutional motivation.
- A rough early PhD introduction can help clarify the project. Revise it when the actual chapters are known; questions may follow the review if that reasoning is needed to establish them. A standalone abstract does not replace introductory orientation.
- Review introductions should name the organizing problem and selection logic.
- Multidisciplinary introductions should define only terms needed for the argument.

## Anti-patterns

- Starting with a dictionary-style definition.
- Citing many facts without explaining the tension between them.
- Claiming novelty without naming the prior-work boundary.
- Previewing every section in a way that reads like a table of contents.
- Using hype to compensate for a weak gap.
- Turning a source's sentence count, three-paragraph preference or word budget into a requirement.
- Presenting possible practical value as an achieved effect, or inventing hypotheses for descriptive work.

## Diagnostic questions

- What does the reader need to know before the gap makes sense?
- Which sentence states the gap?
- Which sentence states why the gap matters?
- Which sentence states what this work does about it?
- Are aim, objectives, questions, and hypothesis doing distinct jobs?
- Does the roadmap reflect the actual artifact rather than a generic table of contents?
- What background can be moved to literature review, methods, or supplement?

## Output patterns / mini-templates

- Introduction arc: `Known context. Persistent uncertainty or limitation. Why that limitation matters. Here we address it by...`
- Gap repair: `Prior work established [X], but [specific unresolved problem] remains unclear because [reason].`
- Aim sentence: `Here, we [approach] to test/measure/resolve [specific question] in [system/context].`
- Significance sentence: `[Established contribution] helps address [supported need]. [Possible use] remains to be tested.` Use only the parts warranted by the actual work.
- Thesis opening map: `Relevant context -> need/question -> contribution and scope -> route through the thesis.` Reorder or expand where the argument and local requirements call for it; this is not a heading quota.

## Examples

Illustrative fixed facts: prior work links several pathways to cell identity, but has not established which regulatory changes precede the first stable lineage decision. This gap must be verified in the user's literature context before adopting it.

Before: `Many pathways regulate cell identity, and this has been studied for decades.`

After: `Although several pathways have been linked to cell identity, it remains unclear which regulatory changes occur before the first stable lineage decision.`

Changed condition: a thesis with a separate critical-review chapter may introduce the competing explanations briefly and direct readers to that chapter. If the approved architecture has no separate review chapter, the introduction may need to compare those explanations and their evidence itself. Keep that critical work; do not cut it merely because it is longer than a paper introduction.

## When not to apply this

Do not use introduction guidance to rewrite a discussion as if it were a setup section; discussions should interpret evidence already presented.
